# Salsabil — native app

The iOS and Android build, sharing its business logic with the web app.

## How code is shared

There is no duplicated logic. Metro is pointed at `../src`, so the mobile app
imports the same modules the web app does:

| Layer | Location | Shared? |
|---|---|---|
| Types, DB schema | `../src/types`, `../src/lib/database.types.ts` | yes, verbatim |
| Supabase API layer | `../src/lib/api/*` | yes, verbatim |
| Reward economy | `../src/lib/rewards.ts` | yes, verbatim |
| React Query hooks | `../src/hooks/*` | yes, verbatim |
| Auth context | `../src/hooks/useAuth.ts` | yes (written with `createElement`, no DOM) |
| Screens / components | `app/`, `components/` | no — React Native has no DOM |

`@/…` resolves to `../src` here exactly as it does on web.

### Platform adapters

Four things genuinely differ between browser and native. Each is a pair of
files resolved by extension — Metro and `tsc` both prefer `.native.ts`:

- `../src/lib/platform/env.ts` — Vite's `import.meta.env` vs `expo-constants`
- `../src/lib/platform/storage.ts` — `localStorage` vs `AsyncStorage`
- `../src/lib/platform/appState.ts` — `visibilitychange` vs `AppState`
- `../src/lib/platform/toast.ts` — `sonner` vs `sonner-native`
- `lib/theme.ts` — the web's DOM class toggling vs NativeWind's `colorScheme`
- `lib/auth.ts` — OAuth page redirect vs deep link through the system browser

Their shared interfaces live in `../src/lib/platform/types.ts`, which has no
platform variant — otherwise `env.native.ts` importing `./env` would resolve
to itself.

### Single-instance packages

`metro.config.js` pins `react`, `react-dom`, `react-native`,
`@tanstack/react-query` and `@supabase/supabase-js` to this project's
`node_modules`. Files under `../src` would otherwise resolve them by walking up
to the web app's `node_modules`, putting two copies of React in one bundle —
every hook then throws "invalid hook call" — and two React Query instances, so
the provider and the hooks would read different caches.

The two apps do **not** share a `node_modules`. NativeWind 4 requires Tailwind
CSS v3 and resolves it from its own directory, while the web app is on Tailwind
v4; an npm workspace hoists NativeWind next to v4 and it refuses to start.

## Setup

```bash
npm install
cp .env.example .env    # then fill in the real values
npm start
```

`EXPO_PUBLIC_API_BASE_URL` must point at the deployed web app. Native builds
have no origin of their own, so `fetch('/.netlify/functions/…')` cannot work —
`../src/lib/api/functions.ts` builds absolute URLs from this value.

Add `salsabil://auth-callback` to Supabase → Authentication → URL Configuration,
or OAuth sign-in will complete in the browser and never return to the app.

## Builds

```bash
npm run type-check                 # tsc, including the shared ../src modules it imports
npx expo export --platform ios     # verify the bundle without native toolchains
npm run build:preview              # EAS: internal build for both platforms
npm run build:ios                  # EAS: App Store
npm run build:android              # EAS: Play Store
```

EAS builds iOS in the cloud, so a Mac is not required. Before the first build,
run `eas init` and set the env vars as EAS secrets:

```bash
eas secret:create --name EXPO_PUBLIC_SUPABASE_URL --value "https://…"
```

`ios/` and `android/` are generated by `npx expo prebuild` and are gitignored —
the native projects are derived from `app.config.ts`, which is the single
source of truth for bundle identifiers, permissions and the deep-link scheme.

## Notifications

Prayer reminders are scheduled **on the device** (`lib/notifications.ts`), not
pushed from a server. They fire at the exact minute, offline, with no VAPID
subscription, no Netlify function and no service worker — which is the single
biggest reason this app is native rather than a PWA, since iOS Web Push only
works for a manually home-screened site and never guarantees delivery.

Focus sessions schedule an end-of-session notification the same way. The timer
itself is already correct while suspended because it reads the wall clock, but
nothing can *tell* the user it finished if the app is not running.

`cancelByKind` exists so a finished focus session does not wipe the day's
remaining prayer reminders — `cancelAllScheduledNotificationsAsync` would.
